# 다중 저장 슬롯

## 완료

페이지당 10개, +로 10개씩 추가하고 이전/다음 페이지를 탐색한다. 빈 페이지 수는 pages.json에 유지한다. Map은 슬롯 선택 후 저장하며 기존 기록의 덮어쓰기를 확인한다. 로비는 선택 슬롯을 계속하거나 두 단계로 삭제한다. 슬롯/페이지 변경은 확인 상태를 취소하며 삭제해도 번호와 페이지는 유지한다.

1번은 기존 run.json을 변경 없이 사용한다. 나머지는 slot_0002.json 등의 독립 파일이다. 같은 판을 여러 슬롯에 저장할 수 있으며 사출/종료 시 동일 runId 사본 전체를 종료 처리한다. 다른 판은 보존한다. 새 게임의 기존 저장 보존과 전투 중 저장 금지도 유지한다.

## 검증

- SaveSlotsVerification.RunFinal: 기존 게임/저장/무결성 회귀, 기본 10개, +10개 연속 추가/재로드, 기존 1번, 독립 저장·백업·삭제·재사용, 선택, 같은 판 사본 종료/다른 판 보존, 페이지 IO 오류 통과.
- SaveSlotsPlayVerification: Map 1/11번 저장 → 덮어쓰기 확인 후 Lobby → 3페이지 추가/이동/선택 변경 삭제 취소 → 11번 계속 → Map 12번 저장 → Lobby 11번만 삭제 통과. 각 슬롯의 고정 크기와 텍스트 높이를 검사했다.
- 저장소를 임시 폴더에 격리해 실제 사용자 파일을 건드리지 않았다. 실제 마우스/스크린샷/해상도별 시각 QA는 별도다.

기존 사용자 폰트와 Obsidian workspace 변경은 제외한다. 슬롯 UI는 SaveSlotBrowser의 런타임 공통 그리드이며 Scene 재생성 도구의 기존 SaveSlotWindow 연결을 그대로 사용한다.
