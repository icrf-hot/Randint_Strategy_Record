# 2026-10-15 Cache 구매와 전투 적용

## 확정 답변

- Q-C01++: Cache는 한 판에 유지, 교환/합성으로 변경 가능. 명시적 새 게임에서 basic 상태로 초기화.
- Q-C04: 기본 HP와 Cache 계산 후 전투 HP 분리. 비율 계산/전투 중 현재 HP·부활은 Q-C07에 남김.
- Q-C05: 한 판 전체 중복 구매 금지. 마지막 보스 엔딩 또는 무결성·정합성 모두 떨어져 사출되면 판 종료. 임계값은 미정.

## 완료 1: 소유·구매 API

- `RunCacheInventory`와 `MapRunState.TryPurchaseCache`: 읽기 전용 보유 목록과 별도 구매 이력, 카탈로그 기반 검증, Packet 차감/획득, 중복/미설정/잔액 부족 차단.
- `CachePurchaseVerification.Run`, `CodexCachePurchase.log`: 종료 코드 0. 실제 플레이 없이 데이터·초기화 API 검증. 실제 씬 전환과 마우스 검증은 별도.
- 상점 UI/노드는 아직 미연결. 판매 목록 갱신 정책을 임의로 정하지 않음.

## 재시작 위치

- 다음 단계: 기존 6종 고정 능력치 Cache를 전투 시작에 적용. 원본 OperatorData와 라운드 보너스는 보존.
- 이후 상점 TMP UI/Shop 노드 연결. Q-C06 보상 Cache와 Q-C07 비율/전투 중 변경은 답변 전 구현하지 않음.
- 사용자 기존 wiki 변경과 Obsidian 배치는 커밋에서 제외. 완료 단위만 검증 후 커밋·푸시.
