# 전투 선택 UI 전경과 AT DF 효과

## 요청과 원인

SR·AT·DF 포지션 표시가 손패에 가려지고 FRONT의 AT/DF 선택 표현이 서로 달랐다. 카드는 최상위 Sorting Layer에서 5000 이상으로 그려지지만 선택 UI는 Default/2~6에 남아 있었다. 토글은 선택 배경과 글자를 모두 Accent로 칠하고 해제 배경은 흰색으로 돌려 글자가 사라지거나 흰 칸이 보였다.

## 변경

- `BattleSelectionPresentation`과 `BattleSelectionPresentationInstaller`가 `Canvas/Base1`, `Canvas/Position`을 SortingGroup 20000으로 묶고 기존 글자 Canvas를 같은 레이어의 20006에 둔다. 내부 Sprite 순서는 유지한다. 카드의 최대 인덱스·호버/선택 상승·숫자 순서도 이보다 낮다.
- 전경 레이어에서도 2D 조명 범위 때문에 UI가 검게 변하지 않도록 두 UI 영역에 전용 `BattleSelectionUnlit.mat`을 적용한다. 전장·카드 그림의 머티리얼은 바꾸지 않는다.
- AT/DF는 동일한 기본/호버/선택 표현을 사용한다. 선택은 청록 바탕+어두운 글자, 해제는 어두운 바탕+밝은 글자다. 호버 전환은 unscaled 시간으로 처리한다.
- Mouse 폴링과 PointerClick은 같은 선택 경로를 사용하며 이미 선택한 버튼의 중복 전달은 무시한다. 기존 그룹·SetAttack/SetDefense 연결과 전투 계산은 유지한다.
- 설정 등 Overlay Canvas와 전투 진행/전환 중에는 토글 입력을 차단한다. 패널에 가려진 카드의 클릭도 차단한다.
- 씬은 이 프로젝트의 Editor API로 수정·저장했다. 원래 프로젝트 설정 변경은 보존했다.

## 검증과 범위

- C# 재컴파일: completed, failed=false, errors=[], compilationFailed=false.
- 이 시각/입력 문제에 필요한 제한 Play 검증만 실행했다. 전투 실행·승패 처리·캠페인 저장은 하지 않았다.
- 프로그램 방식의 UI 이벤트 검증: 카드 8 기준 AT=공격 +800/방어 0, DF=공격 0/방어 +40. 선택 상호 배제, 재전달 시 이벤트 1회, 글자 대비, 초기화, 카드 클릭 관통 방지, 모달 입력 차단을 확인했다.
- 실제 Game View 캡처에서 AT/DF 각각의 선택 상태와 카드 호버 중 SR·AT·DF 전경 표시를 확인했다. 프레임 증가도 확인했다.
- 합성 장치 클릭은 폴링 입력을 안정적으로 재현하지 못해 실제 하드웨어 클릭 검증으로 취급하지 않았다. 전체 마우스 조작·다양한 해상도·출시 빌드 검증은 남아 있다.
- 로컬 캡처는 `Logs/UiCaptures/`에 보관하며 Git 대상이 아니다. 실제 화면 검증을 컴파일 성공만으로 대체하지 않았다.

## 후속 주의

테마를 재적용할 때도 `BattleSelectionPresentationInstaller`의 전경·Unlit 설정을 유지한다. Sorting Layer/카드 최대 순서를 확장하면 UITheme의 카드와 패널 순서 계약을 함께 점검한다. 설정/결과/전환 Overlay는 계속 이 UI보다 위에 있어야 한다.
