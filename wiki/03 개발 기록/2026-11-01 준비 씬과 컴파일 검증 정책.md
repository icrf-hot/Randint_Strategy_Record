# 준비 씬과 컴파일 검증 정책

## 요청과 변경

일반 작업은 컴파일 증명을 기본으로 한다. Unity 실행/갱신은 컴파일에 필요하면 허용되며, 플레이/직접 조작 검증은 특정 문제나 사용자 요청에 한한다. AGENTS.md와 통합 TODO에 기록했다.

현재 프로젝트에 com.unity.pipeline 0.9.1-exp.1을 설치하고 로컬 Codex MCP를 이 프로젝트로 고정 등록했다. Pipeline 7800의 ready, Play stopped를 확인했다. 다른 프로젝트의 Editor/MCP는 사용하거나 수정하지 않았다. CLI 1.0.0-beta.13의 beta.15 업데이트 알림은 알렸고 자동 업데이트하지 않았다. .codex/config.toml은 머신 로컬 경로/localhost 설정이므로 기능 커밋에 포함하지 않는다.

기존 Title/Lobby/Map/Playing 흐름에 Preparation을 추가했다. Lobby 새 게임은 준비 화면만 열며, 작전 시작에서만 기존 새 게임 초기화를 한다. 로비 복귀/계속하기/저장 파일은 보존한다.

Front 사리아/Middle 도로시/Back 조이스 무어를 기존 이미지와 이름으로 표시한다. 변경 버튼은 TMP 경고만 출력한다. 데이터 손실률은 0단계만 표시한다. 실제 상위 단계 디버프와 자유 편성은 구현하지 않았다.

## 구현·검증 범위

- 기존 uGUI/JSON/MenuSceneLoader 패턴을 사용하고 Preparation을 Build Index 5에 추가했다. 기존 인덱스는 변경하지 않았다.
- Editor API로 새 Scene을 생성했다. 빌드 목록이 메모리 등록에만 남아 프로젝트 설정 파일에도 동일한 항목을 명시 반영했다.
- MCP/Pipeline script recompile_status: completed, failed=false, errors=[], compilationFailed=false.
- 기존 FrontEndSceneTests와 RunRecordPlayVerification의 새 게임 경로를 준비 씬에 맞췄다. 테스트 코드는 컴파일했지만 실행하지 않았다.
- Play 진입, 전투 시뮬레이션, 클릭/화면 검증, 전체 시스템 검증은 하지 않았다. 컴파일이 기능 동작/시각 검증을 증명한다고 주장하지 않는다.

사용자 폰트·Obsidian workspace·기획 TODO/코드 TODO 변경은 보존하고 이번 커밋에서 제외한다.
