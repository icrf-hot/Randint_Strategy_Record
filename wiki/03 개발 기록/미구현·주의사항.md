# 미구현·주의사항

현재 작업 트리 기준이다. 과거 기록의 “Title 메뉴/영구 저장/상점 없음”, “Back은 항상 50 회복”, “SP 연결 없음”, “씬마다 독립 로딩 오버레이”는 이후 구현으로 해소되어 현재 공백으로 취급하지 않는다. 상세 완료 현황은 [[00 프로젝트/구현 현황]]을 따른다.

## 전투·연출

- Healer는 선택 카드 합 × 100으로 회복하며 비-Healer BACK의 폴백만 현재 50이다. 기존 대상 선정·피해·턴 순서를 유지한다.
- 적은 물리 공격이며 활동 중인 Front → Middle → Back 우선순위다. 적 AI의 전술 다양화는 남아 있다.
- Middle의 비물리 속성 공식은 현재 대부분 합 × 80으로 동일하다. 속성별 상태 효과·지속 피해와 약점/저항/크리티컬/회피 판정은 구현하지 않았다.
- AttackOutcome/히트 정보의 표시 경로는 판정 규칙 자체가 아니다. SYNC 보너스 규칙과 카드 흡수 연출 연결도 남아 있다.
- MIDDLE 시각 2타는 피해·자연 SP를 1회만 적용한다. 도메인 Impact를 동시에 실행하는 콤보 스케줄러는 추가하지 않았다.
- 실제 공격 AnimationClip과 AudioClip은 미지정이다. 프로파일·이동 모듈·Animation Event 릴레이·사운드 피치/쿨다운 기반을 연결한 뒤 클립별 검증이 필요하다.
- 승리 후 웨이브/적 재생성 정책과 실제 부활·예약 재배치 스킬은 남아 있다.

## UI와 표현

- Playing_Scene에는 기록 HP HUD를 생성하지 않는다. 무결성/정합성 표시를 복구할 경우 현재 카드/스탯 선택창과 겹치지 않는 배치를 먼저 정해야 한다.
- Sprite 기반 선택창의 부모는 비균등 스케일을 사용한다. BattleSelectionPresentationInstaller의 문자 X/Y 보정을 유지하고 숫자 TMP를 비활성화하지 않는다.
- 카드 전방 정렬과 선택창 내부 표시 순서를 구분한다. 모달·설정·전환 화면은 카드 위에 표시되어야 한다.
- 준비 씬은 기존 3명의 포지션별 고정 편성이다. 대원 목록 서랍은 추가 캐릭터/자유 편성을 구현한 것이 아니다. 데이터 손실률 상위 단계도 미구현이다.
- 현재 UI의 Consistency 라벨 “일관성”과 시스템 명칭 “정합성”은 용어 정리가 필요하다.
- 다양한 화면 비율·해상도·실제 마우스 입력 전수 검사와 접근성 체감 조정은 남아 있다. TMP 외곽선의 물리 픽셀 두께는 해상도/배율에 따라 달라진다.

## 맵·런·저장

- Shop 진입/구매/재입장과 다중 슬롯 저장·이어하기·확인 삭제는 구현됐다. Event 노드의 실제 결과 실행기, 루트 분기·최종 보스/유물 엔딩 조건은 남아 있다.
- 무결성 0 사출과 동일 판 저장 종료는 연결됐다. 최종 엔딩 종료 훅은 조건 확정 후 연결해야 한다.
- 정합성 감소 API와 손실 이월은 있지만 감소를 발생시키는 이벤트 규칙은 아직 연결하지 않는다.
- 별도 로딩 이미지 아트, 전환 실패 오류·재시도 UI와 실제 BGM/효과음 청취는 남아 있다.

## 스킬·구조·검증

- JSON 스킬 정의와 실제 공격 시 자연 SP 회복 경로는 있다. 현재 대원의 실제 스킬 효과/발동 연결은 미완료다.
- 싱글턴 수명과 FindObjectsByType 사용 비용은 기능 확장 시 관찰한다. 화면/월드 공간 UI가 공존하므로 현재 씬의 실제 사용 버전을 확인한다.
- 전투 연출 시계는 국소 히트스톱/슬로를 사용한다. 기존 수동 포커스·설정·결과 화면의 timeScale 제어와 혼동하지 않는다.
- C# 컴파일을 기본 검증으로 사용한다. 필요할 때만 특정 이유를 밝히고 런타임 검증하며, 씬 저작/컴파일 성공을 시각·게임플레이 검증으로 기록하지 않는다.
- 최근 제한 검증의 성공은 전체 캐릭터·스킬·밸런스·실기기 성능·출시 빌드/셰이더 스트리핑 검증을 뜻하지 않는다.
