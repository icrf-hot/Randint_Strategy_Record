# 미구현·주의사항

## 플레이 흐름 공백

- `Map_1F`의 Battle 노드 → `Playing_Scene` → 성공/실패 결과 화면 → 현재 노드로 복귀하는 경로는 코드·씬 참조상 구현됨. Read Only 정적 검증만 수행했으므로 실제 플레이 확인은 별도 필요
- `Title` → `Map_1F` 진입 흐름이 없음
- 승리와 재배치 후 활동 대원 0명 패배 판정은 있음. 두 결과 모두 맵으로 돌아가며 런 종료·보상·페널티·웨이브 정책은 없음
- 일반 라운드의 `ResetOperatorBonuses()` 호출이 빠져 이전 보너스가 남을 수 있음. 종료 결과 분기에서만 초기화하므로 다음 코드 작업의 우선 수정 항목임
- 맵으로 돌아갈 때 현재 노드 ID·표시명을 정적 메모리로 복원하며 보상·완료 노드·기타 전투 결과는 반영하지 않음
- 디스크 저장/불러오기와 영속 런 상태 모델이 없음

## 신규 UI 기획과 구현의 경계

- [[04 기획/타이틀·로비 기획|타이틀·로비 및 Map/Battle UI]]는 요구·제안·미결정 사항을 분리한 기획 기록이다. 로비·창 모드·일시정지·저장이 구현되었다는 뜻은 아니다.
- Title→로비→새 게임/이어하기를 구현하려면 현재 카메라만 있는 Title의 UI·진입 라우터와 Build Settings 구성이 필요하다.
- Map `−`의 목적지·복원 방법, `×`의 종료 범위·저장 실패 처리, Battle 나가기의 저장 시점·재진입 기준은 미정이다.
- Battle 중단은 `Time.timeScale = 0`만으로 보장되지 않는다. 기존 실시간 대기·포커스·카드 연출·결과/씬 전환과 입력 차단의 경계를 별도 설계·검증해야 한다.
- Map 전체 화면 복귀는 게임 내부 연출 방향이며 OS 창 모드·해상도 변경으로 확정하지 않는다.

## 로딩 화면

- 맵의 `LoadingCanvas`와 전투의 `BattleEntryCanvas`가 각각 퇴장·진입 페이드를 담당함
- 두 배경 UI Image의 Sprite가 비어 있고 검은색만 사용하므로 최종 로딩 이미지 작업은 미완료
- 씬에 저장된 `battleScenePath`는 `Assets/Scenes/Playing_Scene.unity`이며 Build Settings에도 활성 등록됨
- 별도의 Loading 씬은 없고, 씬마다 독립된 전환 오버레이를 사용하는 인계 방식임
- 전투 진입 중 `Time.timeScale = 0`, 완료 시 1로 복원함. 향후 진입 전 시간 배율 보존이 필요하다면 고정값 대신 이전 값을 저장해야 함
- 로드 실패 시 플레이어에게 보여 주는 오류·재시도 UI 없음
- `BattleToMapSceneLoader`의 비동기 로드 생성 실패 분기는 시간 배율을 복원하지만 이미 표시한 검은 오버레이와 입력 차단을 되돌리지 않음

## 전투·카드

- Back이 선택한 두 카드 숫자는 회복량에 사용되지 않음
- Back 회복량은 고정 50
- 적은 항상 물리 공격이며 Front → Middle → Back 고정 우선순위를 사용
- Middle의 ARTS/BURN/NERVOUS/NECROSIS/CORROSION/조커 공식이 모두 현재 `합 × 80`으로 동일
- 속성 상태 효과와 지속 피해 없음
- 승리 후 적 재생성 또는 다음 웨이브 정책 없음
- 현재 적 프리팹은 JSON ID `makeshift`를 참조함. `Definitions/enemies.json` 값은 HP 1000·공격 2000이며 최종 밸런스 확정 여부는 미확인

## 스킬

- `SkillData` 한 개가 있으나 이름과 설명이 비어 있음
- 모든 대원의 JSON `skillIds`가 비어 있음. ScriptableObject Inspector 스킬 배열 연결 방식은 제거됨
- 부활·재배치 API와 이벤트는 있지만 실제 발동 수단은 연결되지 않음
- SP 회복 이벤트가 전투 코드에 연결되지 않음
- 실제 스킬 효과 계층이 없음

## 맵

- 선택지 문구는 여러 개지만 결과가 모두 동일 노드 이동
- Battle 노드의 전투 씬 진입은 구현됨. Shop/Event 실행기는 없음
- 복귀 위치는 `MapRunState`의 노드 ID로 유지하고 표시명도 함께 저장하지만 애플리케이션 종료 시 보존되지 않음
- `MapRunState.Reset()` 호출처가 없어 새 런 시작 시 초기화 정책이 아직 없음
- `MapPath`는 존재하지만 현재 씬의 일반 MonoBehaviour 목록에서는 사용이 확인되지 않음
- `ThridBoss` enum 명칭에 오타가 있음

## JSON 이전과 검증 한계

- 문구·대원/적/스킬 기본 정의는 JSON으로 이전됨. 씬·Asset의 키/ID가 JSON과 일치해야 하며 누락·중복·잘못된 값은 Catalog 오류로 처리함.
- `GameDataValidationMenu`, 빌드 전 검증 훅, `GameDataCatalogTests`, `GameDataSceneTests`가 추가되었으나 이번 Wiki 작업에서 실행하지 않음. 코드 존재를 테스트 통과로 기록하면 안 됨.
- 현재 언어는 `ko-KR` 하나. 런타임 언어 전환은 없음.
- 노드명·스킬명/설명·캐릭터 대사의 의도적 공백은 `allowEmpty`로 유지됨.
- TMP 동적 폰트에 문자 테이블이 다시 존재하지만 JSON 한글·특수 카드·해상도별 출력은 실제 플레이에서 확인해야 함.

## 구조상 주의

- `BackCardSelectionManager.Instance`를 설정하는 `Awake()`가 주석 처리되어 있음. 현재 전투 초기화는 씬 참조와 검색으로 우회하지만 일관성이 떨어짐.
- 싱글턴의 중복 처리 정책이 클래스마다 다름.
- `FindObjectsByType` 호출이 포커스·타기팅·맵 갱신 때 반복되어 개체 수 증가 시 비용을 관찰할 필요가 있음.
- 일부 UI 클래스가 화면 공간/월드 공간 버전으로 공존해 실제 사용 버전을 문서와 씬에서 계속 구분해야 함.
- 코드 주석과 로그 일부는 파일 인코딩에 따라 깨져 보이므로 향후 UTF-8 통일이 필요함.
- 복귀 페이드가 `Time.timeScale`을 고정값 `1`로 복원하므로 다른 시간 배율을 이어가야 하는 흐름이 생기면 이전 값 저장이 필요함.

## 문서화 시 판정 규칙

> [!important]
> 데이터 정의가 있다고 해서 “플레이 가능”으로 기록하지 않는다. 씬 참조와 호출 경로가 모두 확인될 때 구현 완료로 분류한다.
