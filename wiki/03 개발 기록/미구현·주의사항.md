# 미구현·주의사항

## 플레이 흐름 공백

- `Title` → `Map` → `Playing_Scene` 전환 흐름이 없음
- 전투 승리/패배 및 웨이브 종료 판정이 없음
- 전투 결과를 맵에 반영하거나 맵으로 복귀하는 연결이 없음
- 저장/불러오기 및 런 상태 모델이 없음

## 전투·카드

- Back이 선택한 두 카드 숫자는 회복량에 사용되지 않음
- Back 회복량은 고정 50
- 적은 항상 물리 공격이며 Front → Middle → Back 고정 우선순위를 사용
- Middle의 ARTS/BURN/NERVOUS/NECROSIS/CORROSION/조커 공식이 모두 현재 `합 × 80`으로 동일
- 속성 상태 효과와 지속 피해 없음
- 승리 후 적 재생성 또는 다음 라운드 정책 없음

## 스킬

- `SkillData` 한 개가 있으나 이름과 설명이 비어 있음
- 모든 대원의 `skills` 배열이 비어 있음
- SP 회복 이벤트가 전투 코드에 연결되지 않음
- 실제 스킬 효과 계층이 없음

## 맵

- 선택지 문구는 여러 개지만 결과가 모두 동일 노드 이동
- Battle/Shop/Event 노드 타입별 실행기가 없음
- `MapPath`는 존재하지만 현재 씬의 일반 MonoBehaviour 목록에서는 사용이 확인되지 않음
- `ThridBoss` enum 명칭에 오타가 있음

## 구조상 주의

- `BackCardSelectionManager.Instance`를 설정하는 `Awake()`가 주석 처리되어 있음. 현재 전투 초기화는 씬 참조와 검색으로 우회하지만 일관성이 떨어짐.
- 싱글턴의 중복 처리 정책이 클래스마다 다름.
- `FindObjectsByType` 호출이 포커스·타기팅·맵 갱신 때 반복되어 개체 수 증가 시 비용을 관찰할 필요가 있음.
- 일부 UI 클래스가 화면 공간/월드 공간 버전으로 공존해 실제 사용 버전을 문서와 씬에서 계속 구분해야 함.
- 코드 주석과 로그 일부는 파일 인코딩에 따라 깨져 보이므로 향후 UTF-8 통일이 필요함.

## 문서화 시 판정 규칙

> [!important]
> 데이터 정의가 있다고 해서 “플레이 가능”으로 기록하지 않는다. 씬 참조와 호출 경로가 모두 확인될 때 구현 완료로 분류한다.
