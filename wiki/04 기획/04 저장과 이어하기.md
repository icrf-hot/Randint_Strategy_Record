# 04 저장과 이어하기

상위 문서: [[04 기획/타이틀·로비 기획|타이틀·로비 기획]]

## 사용자 요구

- 로비의 폴더 항목으로 게임을 이어간다.
- 로비의 문서 형태 `.exe` 항목으로 새 게임을 시작한다.
- Map 창의 `×`는 저장하고 나간다.
- Battle 중단 창에는 나가기와 계속하기가 있다. Battle 나가기의 저장 방식은 사용자가 아직 지정하지 않았다.

## 현재 구현과 구분

[[00 프로젝트/구현 현황|현재 구현 현황]]에 따르면 `MapRunState`는 노드 ID·표시명·복귀 플래그만 정적 메모리에 유지한다. 디스크 저장과 런 상태 영속화는 미구현이다. 기존 JSON 정의·문구 관리가 플레이 진행 저장 기능을 뜻하지 않는다.

## 미결정 정책

| 항목 | 결정할 내용 |
|---|---|
| 새 게임 | 초기 노드·대원 상태·진행 데이터 초기화, 기존 저장 덮어쓰기 여부 |
| 이어하기 | 저장 슬롯 수, 복원 위치, 저장 없음·손상 시 처리 |
| Map 최소화 | 메모리 상태 유지 범위, 저장 여부, 다시 여는 방법 |
| Map 닫기 | 로비 또는 앱 종료, 저장 성공 후에만 나갈지, 실패 안내·재시도 |
| Battle 나가기 | 저장 여부, 목적지, 전투 전 또는 전투 중 상태의 보존 |
| Battle 재진입 | 카드·적 난수 및 대원 상태 복원, 전투 처음부터 또는 중간부터 재개 |
| 보존 데이터 | 현재·완료 노드, 성공/실패, 보상·재화, HP·퇴각·SP 등의 범위 |
| 기록 의미 | 전투가 기록 재현·복구·검사 중 무엇인지와 성공/실패의 의미 |

## 검토 제안 · 미확정

- Map 최소화는 실행 중 런을 유지하고 로비로 내려놓는다.
- Map 닫기는 저장 후 로비로 복귀한다.
- Battle 진입 전에 런 상태를 보존하고, Battle 나가기 시 그 상태를 이어하기 기준으로 사용한다.
- Battle을 이어갈 때 해당 전투를 처음부터 시작한다. 전투 중간 저장에 비해 상태 범위가 작지만, 재진입 난수와 반복 보상 방지 정책을 함께 정해야 한다.

## 결정 완료 조건

- 각 화면의 새 게임·이어하기·최소화·나가기·계속하기에서 목적지와 보존 상태가 명확하다.
- 게임 종료 후에도 복원할 데이터와 메모리에서만 유지할 데이터가 구분된다.
- 전투 나가기·패배·승리의 진행 및 보상 처리가 서로 모순되지 않는다.
- 저장 없음·실패·손상 시 플레이어에게 보여줄 동작과 안내가 정해져 있다.
