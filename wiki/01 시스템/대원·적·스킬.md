# 대원·적·스킬

## 대원 데이터 모델

`OperatorData` ScriptableObject가 이름, 설명, 포지션, 세부 클래스, 타깃 필요 여부, 기본 능력치, 스킬 배열을 보관한다. `Operator`는 시작 시 데이터를 런타임 능력치로 복사하고 HP와 전투 보너스를 관리한다.

### Cache와 기본/전투 HP 분리 (2026-10-15)

- `OperatorData.MaxHP`와 `Operator.BaseMaxHP`는 원본 기준 HP다. `Operator.MaxHP`는 Cache 고정 HP 보너스를 더한 전투 최대 HP다.
- `Operator.Awake`에서 한 판 보유 Cache를 집계하여 스냅샷을 만들고, 기존 전투 시작 HP 초기화에 계산된 최대 HP를 사용한다. 원본 OperatorData는 변경하지 않는다.
- `CacheStatBonuses`는 HP·공격·방어·아츠 저항·공격 속도를 전체 아군에게 적용한다. 공격/방어/저항은 런타임 기본값 + Cache + 카드 라운드 보너스로 계산한다.
- `ResetBattleBonus`는 카드 보너스만 지운다. 회복 상한·HP 비율·기존 재배치 복귀는 전투 최대 HP를 사용한다. 새 전투 생성 시 보유 목록을 다시 집계하므로 이전 전투의 퇴각이나 라운드 보너스를 복사하지 않는다.
- 현재 고정 보너스만 지원한다. 비율 HP 계산과 전투 도중 Cache 획득/교환/합성에 따른 재적용·현재 HP·부활 처리는 Q-C07 확정 후 추가한다.
- `CacheOperatorVerification.Run` 비플레이 검증과 `MapBattleRoundTripVerification.RunWithCaches` 제한 왕복 플레이 1회 통과. 스프라이트/해상도별 시각 QA는 별도다.

### 포지션별 허용 클래스

2026-10-13 사용자 결정: 직군은 FRONT/MIDDLE/BACK 세 개이며 기존 `OperatorPosition`이 직군에 해당한다. 세부 직군은 추후 알려줄 예정이므로 아래 기존 `OperatorClass` 목록을 최종 세부 직군으로 확정하지 않는다.

| 포지션 | 허용 클래스 |
|---|---|
| Front | Defender, Guard, Vanguard |
| Middle | Caster, Sniper |
| Back | AttackHealer, Healer, Supporter |

에디터 검증 시 포지션에 맞지 않는 클래스는 기본 클래스(Defender/Caster/Healer)로 교정된다.

## 대원 포커스 UI

대원 클릭 시 `OperatorFocusManager`가 다음을 수행한다.

- 시간을 기본 `1.0`에서 `0.2`로 감속
- 포지션별 카메라 포커스 지점, 줌, 회전값으로 보간
- World Space 정보 UI에 이름, 설명, HP, 공격, 방어, 저항, 속도를 표시
- 적 타깃이 필요한 대원이면 `EnemyTargetingManager.BeginTargeting()` 호출
- 다른 대원 클릭 시 정보 패널을 빠르게 숨긴 뒤 내용 교체

## 퇴각·복귀 상태

- 대원은 HP 0 시 삭제되지 않고 `OperatorBattleState.Retreated`로 유지된다. 어두운 색을 적용하고 포커스와 인디케이터를 해제한다.
- 사용자 결정: 퇴각은 개별 전투 범위다. 전투 1에서 퇴각했어도 전투 2에서는 전투할 수 있다. 현재 코드는 새 전투 생성 시 Cache 적용 최대 HP로 초기화한다. 전투 도중 HP 강화/부활 정책은 Q-C07 대기다.
- 퇴각 대원은 행동 목록·피해·일반 치유·타기팅에서 제외된다. 카드 승인도 해당 슬롯을 요구하지 않는다.
- `Revive(restoredHP)`, `ScheduleRedeployment(turns)`, `ProcessRedeploymentTurn()` 기반과 이벤트가 있다. 실제 스킬에서 이를 호출하는 정책은 아직 없다.
- 최신 Git 프로젝트는 D 드라이브의 이전 쓰러짐/NA/글리치 구현과 별개다. 현재 퇴각 상태를 기준으로 설명한다.

## 적 생성과 위치

`EnemySpawnManager`가 지정 인덱스의 `EnemySpawnPoint`에 적 프리팹을 생성한다. 스폰 지점은 `FrontLeft`, `FrontRight`, `BackLeft`, `BackRight` 위치를 갖고, 생성된 `EnemyTargetable`에 위치가 전달된다.

## 적 타기팅

- Front 대원은 `FrontLeft`와 `FrontRight`만 선택 가능
- Middle과 Back 대원은 모든 위치 선택 가능
- 타깃은 대원별 딕셔너리에 따로 기억됨
- 같은 적을 다시 클릭하면 선택 해제
- 죽거나 존재하지 않는 적은 저장된 선택에서 제거
- 타기팅 가능/불가/선택 상태를 색과 인디케이터로 표현

## 회복 타기팅

Back 행동은 수동 대상 선택이 아니라 `AllyTargetingManager`의 자동 우선순위를 쓴다.

1. 사망하지 않았고 HP가 가득 차지 않은 대원을 후보로 수집한다.
2. HP 비율 오름차순으로 정렬한다.
3. 기본 설정에서는 최대 2명을 선택한다.
4. `SelfPriority` 설정이면 힐러 HP가 임계값 이하일 때 힐러 자신을 먼저 포함한다.

## 스킬

`SkillData`는 스킬명, 설명, 최대 SP, 충전 타입과 충전량을 가진다. `OperatorSkill`은 다음 SP 충전을 지원한다.

- `Natural`: 전달받은 공격 횟수 × 충전량
- `Attack`: 공격 시 충전량 추가
- `DamageTaken`: 피격 시 충전량 추가
- 최대 SP 도달 시 `IsReady == true`
- 활성화 후 SP 초기화

> [!warning] 부분 구현
> 대원은 시작 시 스킬 런타임 객체를 만들지만, 현재 전투 행동·공격·피격 코드가 SP 충전 메서드나 `Activate()`를 호출하지 않는다. `Activate()` 내부 효과도 로그와 SP 초기화만 있으며 실제 `SkillEffect`는 없다.
