# 전투 시스템

> [!implemented] 🟢 구현
> 카드 승인부터 속도 기반 행동 실행, 생존 적 검사, 승리 시 맵 복귀 또는 다음 카드 배분까지 연결되어 있다.

## 진입 조건

`BattleAccessManager.Refresh()`가 아래 조건을 모두 만족할 때만 전투 버튼을 활성화한다.

- 세 선택 매니저와 Front/Middle/Back 대원이 모두 존재
- 활동 가능한 포지션의 카드 선택이 완료. 퇴각 슬롯은 선택을 요구하지 않음
- Front가 활동 중이면 행동이 공격 또는 방어로 결정
- 공격 행동을 하는 대원에게 필요한 적 타깃이 선택됨
- 전투 코루틴이 실행 중이 아님

Front가 **방어**를 선택하면 적 타깃이 필요 없다. `RequiresEnemyTarget == false`인 대원도 타깃 검사에서 자동 통과한다.

## 실행 순서

```mermaid
sequenceDiagram
    participant UI as 전투 버튼
    participant Access as BattleAccessManager
    participant Exec as BattleExecuteManager
    participant Seq as AttackSequence
    participant Actor as Operator / Enemy
    participant Cards as CardSpawner

    UI->>Exec: ExecuteBattle()
    Exec->>Access: CanBattle 확인
    Exec->>Exec: 선택 카드 숫자·역할·위치 스냅샷
    Exec->>Cards: 회수 애니메이션 시작
    Exec->>Exec: 아군 3명 + 생존 적 행동 생성
    Exec->>Exec: 속도 내림차순 정렬
    loop 행동 목록
        Exec->>Seq: 공격/회복 연출 시작
        Seq->>Exec: Impact 1회 커밋 요청
        Exec->>Actor: 기존 피해/회복 적용
        Exec-->>Seq: 확정 OnImpact 결과
        Seq->>Seq: Recovery → Resolve
        Exec->>Exec: 생존 적 검사
    end
    alt 모든 적 처치
        Exec->>Exec: 일반 라운드 정리 중단
        Exec->>Exec: 맵 복귀 로더 호출
    else 적 생존
    Exec->>Exec: 포커스 종료·예약 재배치/패배 검사
    Exec->>Actor: 임시 보너스 초기화
    Exec->>Cards: 회수 완료 대기
    Exec->>Access: 선택 초기화 후 새 카드 배분
    end
```

## 턴 우선순위

1. `AttackSpeed`가 높은 개체가 먼저 행동한다.
2. 속도가 같으면 `TiePriority`가 낮은 순서다.
3. 아군 동률 우선순위는 Front `0` → Middle `1` → Back `2`다.
4. 적은 `100 + EnemyPosition`을 사용하므로 같은 속도에서는 아군 뒤에 행동한다.
5. 자기 차례에 HP가 0이면 행동을 건너뛴다.

## 포지션별 행동

| 포지션 | 행동 | 결과 |
|---|---|---|
| Front | 공격 | 선택 숫자 × 100을 공격 보너스로 더한 뒤 물리 피해 |
| Front | 방어 | 선택 숫자 × 5를 방어력과 마법 저항에 임시 추가, 공격하지 않음 |
| Middle | 공격 | 선택 속성/모드의 공식 결과를 공격 보너스로 더한 뒤 물리 또는 마법 피해 |
| Back | 회복 | Healer는 선택 숫자 2장의 합 × healerCardMultiplier(현재 100)로 아군 최대 2명 회복. 비-Healer 폴백은 현재 50 |
| Enemy | 공격 | 생존한 Front → Middle → Back 순으로 첫 대상을 물리 공격 |

## 피해 공식

```text
물리 최종 피해 = max(1, 공격력 - 대상 방어력)
마법 최종 피해 = max(1, 공격력 - 대상 마법 저항)
```

대원의 전투 중 유효 능력치는 `기본 현재값 + 런 Cache 보너스 + 해당 라운드 임시 보너스`다. 라운드가 끝나면 임시 보너스가 0으로 초기화된다.

## 공격 연출과 설정

- 공격/회복은 Anticipation → Dash → Impact → Recovery → Resolve로 진행한다. 단계 진입·종료 이벤트와 확정 OnImpact를 제공한다. FRONT 방어는 기존 보너스 적용 행동을 유지한다.
- 피해·회복은 전투 로직이 actionId당 한 번 적용한다. 팝업·사운드·이펙트는 실제 전후 HP가 담긴 결과를 구독한다. MIDDLE의 2타는 시각/사운드 에코이며 피해와 자연 SP를 중복 적용하지 않는다.
- FRONT 근접 돌진, MIDDLE 짧은 전진, BACK 제자리 회복 투사체를 사용한다. 원본 Transform/콜라이더는 유지하고 자식 표시 스프라이트에 포즈를 적용한다.
- Resources/CombatFeedback의 슬롯별 프로파일과 Library의 캐릭터 덮어쓰기로 타이밍·이동·히트스톱·흔들림·클립을 조정한다. IAttackMovementModule과 BattleAnimationImpactRelay는 향후 클립 연결용이다.
- 1x/2x/3x와 연출 스킵을 제공한다. 스킵도 남은 행동을 원래 순서로 한 번씩 확정한다. 히트스톱과 사망 슬로는 연출 시계에만 적용하며 전역 timeScale은 변경하지 않는다.
- 기본 자동 확대 포커스는 꺼져 있다. 수동 캐릭터 설명창 포커스는 유지한다.
- 실제 AudioClip은 미지정이다. 약점/저항/크리티컬/회피/SYNC의 판정 규칙은 새로 만들지 않았다.

## 전투 선택창 표시

- Playing_Scene에는 무결성/정합성 기록 HUD를 생성하지 않는다. 해당 런 상태는 맵에서 확인한다.
- 기존 Front/Fight/Medic 패널과 카드 참조를 보존했다. 바탕(2) → 행(3) → 슬롯/승인 배경(4) → 아이콘(5) → Canvas 텍스트(6) 순서다.
- 숫자·+·승인·PHYS/ARTS는 중앙 정렬하고 부모 패널의 비균등 배율을 상쇄한다. 빈 FRONT/BACK 숫자 칸은 공백이며 선택 시 수치를 표시한다.
- 테마 재적용 시 BattleSelectionPresentationInstaller가 같은 보정을 적용한다.

## 라운드 종료

- 대원 포커스 해제
- 세 대원의 전투 보너스 초기화
- 카드 회수 애니메이션 완료 대기
- Front/Middle/Back 선택 초기화
- 기존 카드 파괴 후 새 카드 배분
- 전투 실행 잠금 해제

## 승리와 종료

- 각 행동 코루틴이 끝난 다음 프레임에 `AreAllEnemiesDefeated()`를 호출한다.
- 씬의 모든 `Enemy`가 없거나 HP가 0이면 승리로 처리한다.
- 승리 시 `ReturnToMap()`이 중복 실행을 막고 전투 입력·포커스를 닫은 뒤 `BattleToMapSceneLoader`를 호출한다.
- 승리 분기는 일반 라운드 정리와 새 카드 배분을 건너뛰고 씬 전환으로 종료된다.
- 일반 라운드 행동 종료 후 `ProcessOperatorRedeployments()`를 먼저 실행하고, 활동 가능한 대원이 없으면 `FinishBattle(Failure)`로 종료한다. 패배 시 새 카드를 배분하지 않는다.
- 성공/실패 모두 `BattleResultPresenter.ShowResult()`가 끝난 뒤 맵 복귀를 실행한다. 현재 결과 화면은 시간 기반으로 자동 종료한다.
- 일반 라운드는 패배 분기 이후, 카드 회수 완료 대기 전에 `ResetOperatorBonuses()`를 한 번 실행한다. 성공/실패 분기는 `FinishBattle()`에서 한 번 실행한다. 2026-10-13에 일반 라운드의 누락된 호출을 복구했다.
- 웨이브 진행·재생성 정책은 아직 없다.

## 검증과 연결 문서

2026-10-13 제한 검증: 성공 왕복, HP 1 아군의 적 공격 전멸→패배→맵 복귀, Front만 퇴각한 생존 슬롯 승인, 1턴 예약 재배치의 라운드 말 최대 HP 복귀를 실제 씬에서 확인했다. 일반 라운드에서 Front/Middle/Back 임시 공격·방어·저항 보너스가 모두 0이 됨도 검사했다. 패배 결과 중 활성 카드가 없고 새 카드 배분 로그가 최초 1회뿐임을 확인했다. 수치 조정은 테스트 런타임 전용이며 프리팹 저장은 하지 않았다. 마우스/시각 QA는 미실시다.

2026-11-01에는 배속·타격 전후 스킵의 결과/순서 일치, 1회 커밋, 처치·승리 보상·맵 복귀와 선택창 실제 표시를 제한 검증했다. 전체 밸런스·출시 빌드 검증을 뜻하지 않는다.
