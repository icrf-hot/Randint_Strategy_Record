# 우연한 만남

## 현재 범위

명일방주 통합 전략의 비용·보상 거래, 안전하게 떠나기, 조건부 선택이라는 구조를 참고하되 문구와 사건은 이 게임의 기록 단말 컨셉에 맞춰 작성했다. 전투 카드의 숫자를 검증 조각으로 사용하는 고유 사건 **「서명이 일치하지 않는 복구 요청」**을 추가했다. 원작의 개별 이벤트 문구를 복제하지 않는다.

각 층에서 실제로 처음 접속한 우연한 만남에 이 사건을 배정한다. 따라서 해당 층에서 만남 노드를 전혀 방문하지 않는 경로라면 등장하지 않는다. 한 층에 한 번이며, 다른 만남에는 보급 버퍼·유지보수 단말·출처 불명 백업을 배정한다. 보급 버퍼만 반복 가능한 폴백이다. 일반 사건의 일회 제한은 한 판 전체다.

## 서명이 일치하지 않는 복구 요청

같은 기록에서 본문은 같고 서명이 다른 A/B 복구 요청이 도착한다. 격리된 숫자 카드 6장 중 조건에 맞는 조각을 고르면 로컬 검증기가 유효한 채널을 판별한다. 채널을 감으로 고르는 확률 도박이 아니다.

1. 카드 클릭으로 검증 조합을 만든다. 선택·해제와 틀린 조합에는 비용이 없다.
2. 조건이 모두 맞고 Packet이 충분할 때만 **서명 검증**이 활성화된다.
3. 검증 실행 시 Packet을 한 번 지불한다. 유효 채널이 공개되고 카드 조합은 고정된다.
4. **검증된 채널 복구 / 보상 수령**으로 확정 보상을 한 번 받는다.
5. 검증 전에는 **격리하고 떠난다**로 비용 없이 완료할 수 있다. 검증 후에는 수령 전 다른 노드로 이동하지 못한다.

| 층 | 정상 검증 조건 | 검증 비용 | 정상 확정 보상 | JK 우회 비용 |
|---|---|---:|---|---:|
| 1 | 2장·합계 | 무료 | Packet +4 / 무결성 +3%p | JK 없음 |
| 2 | 3장·합계 | Packet 2 | Packet +8 / 무결성 +5%p | 정합성 2%p |
| 3 | 3장·합계·짝수 개수 | Packet 4 | Packet +12 / 무결성 +7%p | 정합성 4%p |
| 4 | 4장·합계·짝수 개수·체크섬 mod 3 | Packet 6 | Packet +18 / 무결성 +10%p | 정합성 6%p |
| 5 | 4장·합계·짝수 개수·체크섬 mod 5 | Packet 8 | Packet +24 / 무결성 +14%p | 정합성 8%p |

수치는 **구현용 초기 밸런스 값**이다. 보상 Packet은 총 지급량이며 정상 경로의 순증은 검증 비용을 뺀 4/6/8/12/16이다. 무결성은 100%를 넘지 않고, 결과 창에는 실제 변화량을 표시한다.

체크섬은 선택한 카드의 `값 × 왼쪽부터 위치(1~6)`를 더해 modulus로 나눈 나머지다. 현재 합·짝수 수·체크섬을 화면에서 확인한다. 1~2층에는 아직 사용하지 않는 조건을 표시하지 않는다. 모든 패는 정상 검증 해답이 최소 한 개 있도록 생성하며 JK가 있어도 일반 숫자만으로 풀 수 있다.

### JK와 정합성

- JK는 2~5층에서 각각 5/10/12/15% 확률로 마지막 자리에 등장한다. 정상 검증용 숫자 카드가 아니라 **서명 위조 우회**를 여는 선택이다.
- JK를 선택한 뒤 우회를 실행하면 Packet 검증료 없이 해당 층 Packet 보상만 받는다. 무결성 복구는 받지 못하며 사건이 완료된다.
- 정합성 비용은 고갈 시 무결성으로 이월한다. 실행 전 두 수치의 예상 변화를 표시하고, 비용으로 무결성이 0이 되는 선택은 차단한다.
- 정합성 60% 미만에서는 미검증 수신 본문을 격리하고 선택적 보조 힌트를 제공하지 않는다. 검증 조건·비용·확정 보상을 거짓으로 표시하거나 버튼 위치를 바꾸지는 않는다.

## 일반 만남 풀

| 사건 | 선택 |
|---|---|
| 남겨진 보급 버퍼 | 안전한 Packet 회수 / 유료 또는 무료 기록 복구 / 떠나기 |
| 무인 유지보수 단말 | 기록 복구 / 안전한 Packet 회수 / 떠나기 |
| 출처 불명의 백업 | 정합성 비용을 내고 더 큰 Packet 회수 / 안전한 소액 회수 / 떠나기 |

층별 안전 보급은 3/4/4/5/6 Packet, 기록 복구 비용은 0/3/5/8/10 Packet, 두 기록 HP의 복구량은 각각 4/6/8/10/14%p다. 백업의 정합성 비용은 0/2/4/6/8%p, Packet 보상은 4/7/10/14/18이다. 모든 비용은 실행 전에 확인하고 손실·회복은 상한 및 이월 규칙을 따른다. 사건 보상에는 승리 보상용 Cache 배율을 적용하지 않는다.

## 결정성과 저장

- `EncounterJournal`에 사건 ID, 방문 배정 순서, 층별 수치 사본, 카드 패, 조건, 선택 마스크, 판별 채널, 진행 상태와 실제 결과를 기록한다. 런 GUID·노드 ID·용도별 안정 해시를 사용한다.
- 사건 상태는 `Assigned → Verified → Resolved`이며 일반 사건·JK·떠나기는 Assigned에서 바로 Resolved로 간다. 비용과 보상 처리는 UI와 분리된 `EncounterService`가 담당하고 중복 실행을 거절한다.
- 저장 schema **v4**에 사건 원장을 추가했다. v1/v2/v3은 빈 원장으로 호환 복원하며 기존 완료 노드를 미완료로 되돌리지 않는다. 저장 시점의 원장에 포함된 미완료 사건은 같은 패·조건·비용·진행 상태를 유지한다.
- **잠시 닫기 / 진행 상태 유지** 후 기존 맵 설정에서 명시적으로 저장한다. 자동 저장은 추가하지 않았다. 검증료 결제 후 저장한 판은 이어하기 시 보상 수령 단계로 다시 열며 결제하지 않는다. 저장 전 시점으로 되돌아가는 일반적인 수동 불러오기까지 막는 기능은 아니다.
- 원장은 대원·Cache·방문 노드 검증과 함께 검사한다. 비정상 패·조건·상태·완료 여부·중복 사건을 거절한다. 기존 전투의 카드 배분·피해·턴 규칙은 변경하지 않았다.

## 담당 파일

- `Assets/Resources/Campaign/encounters.json`: 사건 풀, 층별 난도·비용·보상.
- `Assets/Resources/GameData/Localization/ko-KR/encounters.json`: 서사·조건·선택 문구. manifest에 등록.
- `Assets/Map/Script/EncounterCatalog.cs`, `EncounterJournal.cs`, `EncounterService.cs`, `EncounterWindow.cs`: 정의·원장·거래·별도 uGUI.
- `CampaignMapFlow`는 Event 선택을 단일 접속 버튼으로 통일하고 별도 창을 연다. 전투용 Card의 싱글턴을 재사용하지 않는다. 색·폰트·버튼은 UITheme/TerminalUI를 사용한다.

## 검증과 후속 작업

2026-11-02, Unity 6000.3.11f1에서 C# 컴파일 통과. `EncounterVerification`으로 층당 500개, 총 2,500개 패의 해답 존재·결정성, 비용·확정 보상·중복 지급 차단, 검증/완료 원장의 파일 왕복, v1~v3 마이그레이션, 손상 데이터 거절, JK 정합성 이월/치명적 비용 차단과 무료 이탈을 확인했다. 기존 층 연결·유물·저장 검증도 통과했다.

비용·저장·UI 가림을 확인할 필요가 있어 제한 Play Mode 검증을 별도로 수행했다. 실제 MapChoice → 카드 버튼 포인터 레이캐스트 → 1/5층 검증·수령, 설정 창 저장 → 맵 재진입 시 검증 상태 재개, 미수령 이동 차단, 저정합성/JK 표시와 실제 손실, 모달 해제 및 텍스트 범위를 확인했다. 임시 저장소만 사용하고 Play Mode 종료 후 원래 씬으로 복귀했다. 전체 런 완주·정식 밸런스·모든 화면 비율·출시 빌드 검증은 아니다.

남은 기믹은 이벤트 전용 전투, 카드 속성 판정, Cache 보상 거래, 맵 간선 변형, 지연 결과, 대원별 반응, 이전 판 잔해와 히든 루트 연결이다. 현재 구현으로 취급하지 않는다.
