# 상점 시스템

> [!partial] 데이터 기반만 구현
> 상점은 Cache를 판매하고 Packet을 재화로 사용한다. 상품 7종 정의와 지갑/Layer 보상 기반은 있으나 구매 UI, 소유·장착, 실제 강화는 아직 연결하지 않았다. 7번째 보상 Cache는 수치 미설정 상태다.

## 사용자 결정

- Cache는 주로 자신의 오퍼레이터 능력치를 강화하는 유물이다.
- 기존 능력치 강화 6종에 Packet·경험치 버프 1종을 더해 임시 7종으로 구성했다. 7번째는 가격·강화량·연산 답변 대기 상태의 정의만 추가했다.
- 결제 재화 이름은 `Packet`이다.
- 이번 작업은 기능 구현을 위한 데이터까지만 추가한다.

후속 사용자 결정: 현재 중복 구매는 금지한다. 미래 N개 중복/부품 조합은 보류다. 현재 임시 Cache는 글로벌 버프이며 능력치 6종은 전체 아군, 추가 1종은 Packet·경험치 획득량을 대상으로 한다. 직군은 FRONT/MIDDLE/BACK = 기존 포지션이고 세부 직군은 추후 결정한다. 사이클/로비 종료 시 Cache 보존·초기화는 추가 답변이 필요하다.

Packet은 새 런 30개, 승리 8개, Layer 상승당 10개를 지급한다. 경험치와 상세 검증은 [[01 시스템/Layer와 Packet|Layer와 Packet]]을 기준으로 한다.

## 데이터 구성

| 타입 | 역할 | 현재 Asset |
|---|---|---|
| `CacheData` | ID, 이름, 설명, 아이콘, 효과 종류, 설정 상태, Packet 가격, 고정 능력치 보너스 | `Assets/Shop/Data/Cache_*.asset` 7개 |
| `PacketCurrencyData` | 재화 ID, 표시명, 설명, 아이콘 | `Assets/Shop/Data/Packet.asset` |
| `ShopCatalogData` | 재화 참조와 판매 Cache 목록 | `Assets/Shop/Data/PrototypeShopCatalog.asset` |

Unity Inspector에서 각 Cache의 가격과 보너스를 수정할 수 있다. `Create > Game > Shop`에서 새 데이터도 생성할 수 있다. `OperatorData`는 원본 능력치 데이터이며 이번 Cache 정의가 이를 변경하지 않는다.

## 임시 상품

아래 이름·가격·강화량은 기능 개발용 임시 값이며 최종 밸런스가 아니다. 기존 능력치 5종의 개별 강화와 종합 강화로 총 6종을 구성했다. 모두 고정 수치 추가 데이터이며 퍼센트 강화로 해석하지 않는다.

| Asset | 표시 이름 | 임시 보너스 | 가격 |
|---|---|---|---|
| `Cache_HP` | 생명력 Cache | 최대 HP +100 | 10 Packet |
| `Cache_Attack` | 공격력 Cache | 공격력 +10 | 10 Packet |
| `Cache_Defense` | 방어력 Cache | 방어력 +10 | 10 Packet |
| `Cache_ArtsResistance` | 아츠 저항 Cache | 아츠 저항 +5 | 10 Packet |
| `Cache_AttackSpeed` | 공격 속도 Cache | 공격 속도 +1 | 10 Packet |
| `Cache_AllStats` | 종합 강화 Cache | 최대 HP +50, 공격력 +5, 방어력 +5, 아츠 저항 +2, 공격 속도 +0.5 | 10 Packet |
| `Cache_Rewards` | Packet / EXP Cache | 글로벌 재화·경험치 획득 강화 정의, 수치/연산 미정 | 미정·구매 불가 |

`CacheEffectKind.GlobalOperatorStats`는 전체 아군 능력치, `GlobalPacketAndExperience`는 재화·경험치 보상 대상으로 구분한다. `configurationPending`은 Inspector에서 미설정을 표시한다. 현재 `IsConfigured`는 설정된 능력치 Cache만 true이며 보상 효과 구현 전에는 보상 Cache를 활성화하지 않는다. 보상 Cache의 직렬화 가격 0은 미정 저장값이지 무료 판매 가격이 아니다. 추후 구매 계층은 반드시 설정 여부를 확인해야 한다.

아이콘은 미지정이다. 판매 재고·Cache 종료 시점·최대 HP 강화 시 현재 HP 변화는 미확정이다. 현재 중복 구매 금지·글로벌 적용은 설계 확정이며 실제 구매/강화 계층은 아직 없다. 7번째 Cache의 가격·Packet/EXP 강화량과 계산은 Q-C06에서 확인한다.

## 검증

- Unity 6000.3.11f1 batch 컴파일 및 `ShopDataVerification.Run` 통과, 종료 코드 0.
- `CodexGlobalCacheData.log`: 카탈로그의 Packet 참조, 상품 7개, Cache ID 중복/빈 이름, 음수 가격·보너스, 능력치 상품 6개와 명시적 미설정 보상 상품 1개를 검사했다. 종료 코드 0.
- 플레이 모드와 구매 테스트는 실행하지 않았다. 상점 노드 8과 카탈로그의 씬 연결은 아직 없다.

## 다음 단계

1. Cache 대상/지속 기간과 직군·세부직군 모델 매핑을 정한다. Packet 지급·승리 보상·Layer는 연결 완료다.
2. 카탈로그를 읽는 상점 UI/TMP와 Shop 노드 진입을 연결한다.
3. 구매 승인·Packet 차감·Cache 소유·런 상태 유지 계층을 구현한다.
4. 대원 런타임 보너스에 Cache 효과를 적용하고 씬 전환·새 런 초기화를 검증한다.
