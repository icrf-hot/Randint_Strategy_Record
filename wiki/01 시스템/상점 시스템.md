# 상점 시스템

## 현재 구현

- 맵 Shop 노드 8 선택 → 별도 `Assets/Scenes/Shop.unity` → 맵 복귀를 연결했다. Build Settings에 Shop을 추가했다.
- Shop Scene의 `ShopSceneUI`가 7종 상품, 강화량, Packet 가격·잔액, 판매 완료·잔액 부족, 구매 결과와 맵 복귀 버튼을 TMP/UI로 만든다. Input System UI 모듈과 기존 한글 TMP 폰트를 사용한다.
- 목록은 스크롤 가능하며 상점 재입장에도 판 전체 구매 이력과 Packet, 현재 맵 노드를 유지한다.
- 실제 마우스 클릭·해상도별 시각 QA는 별도다. 테스트는 UI 이벤트 호출로 검증했다.

## 확정 정책

- Cache는 한 판 동안 계속 보유하고 효과가 유지된다. 로비의 명시적 새 게임에서 기본 상태로 초기화한다. 계정 영구 보유를 뜻하지 않는다.
- 중복 구매 금지는 상점별이 아니라 판 전체다. 보유 목록과 구매 이력은 분리되어 있다.
- 임시 7종을 고정 판매한다. 교환·합성으로 소멸/변경하는 시스템과 N개 중복/상위 곱연산 Cache는 향후 작업이다.
- 현재 능력치 강화는 전체 아군 대상이며 직군은 FRONT/MIDDLE/BACK = 기존 포지션이다.

## 데이터와 구매

- 2026-10-15 JSON 통합: 가격/효과는 Definitions/caches.json, 판매 ID 목록은 Definitions/shops.json, 진행/전투 기본값은 Definitions/run_rules.json, 상품/상점/HUD 문구는 Localization/ko-KR/shop.json을 기준으로 한다. 기존 SO는 definitionId와 아이콘/Scene 참조를 유지한다.
- `CacheData`: ID·표시명·효과 종류·설정 여부·가격·능력치/보상 수치.
- `ShopCatalogData`: Packet 재화 참조와 7종 판매 목록.
- `MapRunState.TryPurchaseCache(catalog, id)`: 카탈로그·고유 ID·설정·판 전체 구매 이력·잔액을 확인하고 차감/획득. 실패 시 상태 불변.
- `MapRunState.Caches.Owned`: 읽기 전용 보유 목록. `HasPurchased(id)`: 판 전체 구매 이력. EnsureStarted는 유지, StartNewRun/Reset은 초기화한다.
- Scene 변경은 `ShopSceneRouter`가 중복 요청을 막고 수행한다. Shop Scene 단독 시작도 진행 설정으로 초기화할 수 있다.

## 전투·보상 적용

- 전투 생성 시 `CacheStatBonuses`로 기존 6종 고정 보너스를 집계한다. 원본 OperatorData·기본 HP를 바꾸지 않고 실제 전투 스탯에 적용한다. 카드 라운드 보너스 초기화에도 유지한다.
- 퇴각은 해당 전투 Scene에만 존재한다. Map에서 저장/계산하지 않고 다음 전투에서는 모두 활성 상태로 시작한다.
- 보상 Cache는 승리 Packet 8→12, EXP 12→18. Layer 요구치와 Layer 상승 10 Packet은 바꾸지 않는다. 반올림은 0.5 이상 올림이다.
- 현재 등급은 기본 고유 스탯 기준 합연산이다. 비율 필드 확장과 상위 곱연산 Cache는 별도 TODO다.

## 검증

- ShopDataVerification / CachePurchaseVerification: 7종·8~32 가격·보상 50%·중복/잔액/잘못된 데이터·초기화 검증.
- RunProgressionVerification: 반올림·Layer 추가 Packet 제외·요구치·오버플로.
- CacheOperatorVerification: 원본 보존·기본/전투 HP·회복 상한·퇴각/재배치·라운드 초기화.
- ShopSceneVerification, CodexShopRoundTrip.log: 맵 선택지→Shop UI 구매/실패→맵 노드8 복귀→재입장 유지 제한 플레이 1회 통과, 종료 코드 0.
- 시각 QA와 실제 포인터 입력은 미실시. 저장·이어하기는 아직 미구현이다.
