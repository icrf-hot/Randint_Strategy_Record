# 무결성과 정합성

RANDINT STRATEGY RECORD의 작전 기록 상태이자 사용자 HP다. BATTLE 대원의 HP·퇴각과 별개이며 한 판 전체에 유지한다.

## 확정 규칙

- 무결성(Integrity), 정합성(Consistency)은 각각 100%로 시작한다. 내부 값은 정수 백분율 포인트이며 범위는 0~100이다.
- 전원 퇴각 패배 확정 시 생존 적 1명당 무결성 10%p를 한 번 차감한다. 예: 적 3명 생존이면 100% → 70%. 승리에는 손실이 없다.
- 정합성은 감소 원인을 연결하지 않는다. 별도 API 호출 때만 감소한다.
- 정합성 손실은 정합성을 먼저 소모하고 남은 손실을 무결성으로 넘긴다. 예: 정합성 20%에서 30%p 손실이면 정합성 0%, 무결성 -10%p. 정합성 0% 이후에는 손실 전부가 무결성으로 간다.
- 무결성 0%는 정합성 잔량과 관계없이 완전 패배(Ejected)다. 전투에서는 기존 패배 결과 연출 후 로비로 간다. 일반 감소 API로 Map 등에서 소진되면 로비로 복귀한다.
- 사출 시 같은 판의 이전 수동 저장도 종료 처리하여 계속하기를 거절한다. 다른 판의 슬롯은 변경하지 않는다. IO 오류 시 종료 기록 후 대체 삭제를 시도하고 실패를 로그로 알린다.
- 로비 방문만으로 초기화하지 않는다. 새 게임에서 두 HP를 100%로 초기화한다.

## 코드와 데이터

- `MapRunState.RecordHealth`: 현재 두 수치.
- `RunRecordHealth`: 수치 범위·손실 이월·복원.
- `RunRecordService.ReduceIntegrity(int)`, `ReduceConsistency(int)`: 향후 이벤트에서 사용할 감소 API. 음수와 종료 판은 거절하며 0% 사출도 처리하므로 외부에서는 이 API를 사용한다.
- `RunRecordService.ApplyBattleDefeat(int)`: 생존 적 수에 따른 전투 손실. BattleExecuteManager의 중복 종료 방지 이후 호출한다.
- `Resources/GameData/Definitions/run_rules.json`의 `defeatIntegrityLossPerEnemy: 10`: 적 1명당 손실.
- Map의 기존 상태 TMP 두 개에 `RunRecordStatusText`를 연결했다. `Integrity 100%`, `Consistency 100%`처럼 표시하고 자동 크기 조절한다. 노드 설명 TMP에는 연결하지 않았다.
- 저장 v2에 수치를 포함한다. v1 파일은 각 100%로 호환 복원한다. Active 상태의 무결성 0 또는 범위 밖 수치는 거절한다.

최종 보스/유물 엔딩과 정합성 감소 이벤트는 이번 범위에 포함하지 않는다.
