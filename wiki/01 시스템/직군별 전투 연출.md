# 직군별 전투 연출

## 현재 적용

| 행동 | 현재 연출 | 논리 처리 |
|---|---|---|
| Front AT | 근접 준비·돌진·타격·원위치 복귀, AT/피해 타입·입력 수치 | 기존 공격 계산과 1회 피해 유지 |
| Front DF | 제자리 방어 자세·방패 윤곽·GUARD·DEF/RES 가산량 | 기존 방어 보너스 시점 유지, 피해/자연 SP 공격 횟수 추가 없음 |
| 도로시 | 줌인·적 조준·제자리 반동·짧은 고속 투사체/꼬리·복귀 | 기존 PHYS/ARTS 선택·피해·턴 순서 유지, 실제 타격 1회 |
| 현재 Back 힐러 | 시전자 링·회복 대상 각각으로 흐르는 곡선·초록 십자·실제 회복량 | 기존 카드 회복량·우선순위·최대 대상 수 유지 |

이동·크기·회전은 `CombatSpriteVisual`의 자식에만 적용한다. 논리 오브젝트/충돌체 위치는 바꾸지 않는다. 전투 배속·스킵·모션/섬광 감소·국소 히트스톱은 기존 공통 시계를 사용한다. 도로시 줌은 일시적인 카메라 제어권을 얻어 수동 포커스와 충돌하지 않게 하고 행동/스킵 종료 시 위치·확대율을 복원한다.

도로시는 현재 게임 JSON에서 Caster다. 원본 직군/피해 규칙을 바꾸지 않고 캐릭터 전용 프로파일로 사격을 지정했다. 일반 Middle의 시각 2타 기본값 대신 도로시는 시각/논리 모두 1타 사격이다. 별도 도트/스켈레탈 애니메이션 클립이나 사운드 자산은 이번에 추가하지 않았다.

## 프로파일 선택과 세부 직군

`Resources/CombatFeedback/Library.asset`은 캐릭터 → 일치하는 세부 직군(branchId) → 직군 → 행동/포지션 기본값 순서로 고른다. 방어는 공격과 별도 프로파일이다.

- Front: Defender/Guard/Vanguard의 공통 근접·방어 템플릿.
- Middle: Sniper의 사격, Caster/Specialist의 시전 템플릿. Specialist는 기존 enum 정수 값을 보존하도록 마지막에 추가했다.
- Sniper + JSON `branchId: "heavy_shooter"`: 더 긴 준비·강한 반동·두꺼운 탄체를 가진 `HeavyShooterShot` 템플릿. 현재 해당 캐릭터를 새로 만들지는 않았다.
- Back: Healer의 치유, Supporter/AttackHealer의 공격 시전 템플릿. 후자는 연결 준비 상태이며 아래 검증 제외 범위를 따른다.

`AttackFeedbackProfile`에서 motion, focusZoom/focusTargetBias, recoilPixels, leanDegrees, projectileLength/Width/Arc, 단계 시간·히트스톱·사운드를 조절한다. 기존 Front/Middle/Back/Enemy 기본 자산은 보존하고 GuardStance/DorothyShot/SniperShot/HeavyShooterShot/CasterCast/HealerPulse/SupportCast를 추가했다. 설치 메뉴 `Tools > Randint > Install Role Combat Templates`는 기존 캐릭터/직군 설정과 생성된 프로파일의 디자이너 조정을 덮어쓰지 않는다.

## 공용 이벤트와 애니메이션 연결

기존 Anticipation → Dash → Impact → Recovery → Resolve와 `AttackSequence.RequestImpact()`의 중복 방지 게이트를 재사용한다.

- 요청에 `CombatActionKind`(Attack/Defense/Heal/SupportAttack), 복수 회복 대상, 방어/저항 가산량을 포함한다.
- `BattleFeedbackDirector.ActionStageEntered/Exited(request, sequence, stage)`로 누가 어떤 행동을 하는지 포함해 단계 진입/종료를 구독한다.
- 확정 피해·치유는 기존 `OnImpact`로 발행한다. 방어는 피해처럼 취급하지 않고 별도 `OnDefense(request)`를 한 번 발행한다.
- 개별 캐릭터의 시각 자식에 `CombatAnimationTemplate`을 연결하고 visualAnimator와 프로파일의 animationTrigger를 지정한다. 단계별 UnityEvent에 캐릭터 전용 효과를 연결할 수 있다.
- 클립이 타격 프레임을 결정하면 `animationDrivenImpact`를 켜고 해당 프레임의 Animation Event에서 `CombatAnimationTemplate.OnImpact()`를 호출한다. 이벤트가 빠져도 Impact 단계 종료의 기존 폴백이 한 번 실행한다.
- 클립이 시각 자식의 Transform을 제어하면 `useProceduralMotion`을 끈다. 원본 스프라이트의 Animator 프레임 변화는 표시 복제본에 동기화한다. 논리 루트에 루트 모션을 적용하지 않는다.

## 서포터: 구현하되 실행 검증하지 않은 확장

사용자 요청에 따라 현재 Healer를 바꾸거나 서포터를 테스트 편성에 넣지 않았다. 아래는 향후 데이터/캐릭터 연결용이며 실행 정확성을 확인한 기능으로 표기하지 않는다.

- Back의 Supporter/AttackHealer는 적 대상 공격 분기로 들어갈 수 있다. 해당 캐릭터는 `requiresEnemyTarget=true`와 실제 적 선택이 필요하다.
- 현재 확장 기본 공격은 기본 ATK의 ARTS 공격이다. 새로운 카드 기반 서포터 피해 공식은 정하지 않았다.
- 선택적 JSON `damageHealingRatio`(0~1, 기본 0)가 양수이면 실제로 제거한 HP × 비율을 내림한 수치를 기존 아군 회복 대상에게 적용하는 연결을 구현했다. 오버킬 입력 공격력이 아닌 실제 피해를 기준으로 한다. 현재 3명은 이 값을 설정하지 않는다.
- `BattleExecuteManager.OnDamageHealingResolved(damageHit, healingHits)`로 공격과 후속 치유의 관계를 구독하며 각 확정 치유도 공통 OnImpact 경로를 사용한다.
- 서포터 추가 시 카드 공식, 공격 타입, 회복 대상/비율과 애니메이션을 확정하고 별도 검증해야 한다. 이번에는 이 분기를 호출하거나 테스트하지 않았다. 전체 C# 컴파일에 포함되는 것만 확인했다.

## 2026-11-18 후속: 전투 가독성 속도와 ESC 순서

사용자 요청에 따라 공통 `AttackFeedbackLibrary.basePlaybackSpeed`를 0.3으로 설정했다. 표시되는 1x는 이전 연출 시계 대비 약 3.33배 긴 기본 재생이며 2x/3x는 이 새 기준의 배속이다. 단계·투사체·히트스톱·팝업·회복 표시·연출 대기를 같은 시계로 늦추고 UI 자체는 기존 속도로 유지한다. `maxActionGap=0.18`로 늘려 씬의 0.5초 간격과 비교한 최종 대기는 1x에서 약 0.6초다. 값은 Library Inspector에서 조절한다. Time.timeScale로 전체 게임을 느리게 만들지는 않는다.

ESC는 `TerminalSettings.HandleEscape()` 한 곳에서 키 입력을 받는다. 열린 전투 옵션/설정/로비 모달을 닫는 처리를 먼저 하고, 그렇지 않으면 준비 목록 → 대원 포커스/타깃 선택창 → 맵 포커스를 우선 취소한다. 취소할 포커스/목록이 없으면 설정을 연다. 각 단계는 처리 즉시 반환하므로 한 번의 키 입력이 취소와 설정 열기를 동시에 실행하지 않는다. 대원 포커스의 취소는 기존 ExitFocus 동작이며 이미 배정한 카드/대상 데이터의 일괄 초기화를 뜻하지 않는다. 전투 실행 중 자동 연출 포커스는 사용자 선택 취소로 취급하지 않는다.

대원·맵·준비 화면에 분산돼 있던 ESC 키 검사는 제거했다. 따라서 MonoBehaviour.Update 실행 순서에 의존하지 않는다.

검증: C# 컴파일 완료. 격리 Play Mode에서 실제 Input System ESC 상태를 입력해 ① 선택만 취소·시간 정상화 ② 설정 열기·일시 정지 ③ 설정 닫기·재개를 확인했다. 느린 기준의 도로시 사격은 약 1.77초(프로파일 단계 합의 이론 최소 1.57초 + 국소 히트스톱)로 측정했다. Front 공격/방어, Back 2명 치유, 도로시 스킵과 루트/카메라 복원도 통과했다. 서포터 분기는 이번에도 실행하지 않았다. 맵/준비의 우선 취소는 코드 연결·컴파일 확인 범위이며 별도 런타임 입력 검증은 하지 않았다.

## 2026-11-18 후속: 확대 완료 후 발사·탄환 추적·피격 결과 대기

사용자 요청에 따라 Shooting 템플릿의 카메라 순서를 바꿨다. Anticipation에서 공격자에게 줌인하고, Dash 시작에 발사한 뒤 탄환 경로를 따라 화면을 이동하며 줌을 해제한다. Dash 종료 시 원래 전장 구도로 돌아오며 Impact에서 기존 단일 적용 게이트로 피해를 확정한다. Recovery/결과 표시는 전장 구도를 유지한다. 적이 피격 후 사라져도 카메라 추적이 갑자기 공격자로 되돌아가지 않도록 시퀀스 시작 시 시전자/대상 중심을 복사한다.

현재 도로시의 프로파일 시간은 준비 0.18 / 비행 0.24 / Impact 0.08 / 복귀 0.15 연출 초다. 1x의 공통 0.3 시계에서 준비 약 0.6초, 탄환 비행 약 0.8초이며 히트스톱과 결과 대기는 별도로 더해진다. UI나 논리 루트 이동 속도는 변경하지 않았다.

프로파일에 `resultHold`(기본 0.12 연출 초)를 추가했다. 사격은 기존 체력바의 hpDelay+hpCatchup이 끝날 시간을 복귀 뒤에도 확보한다. `BattleFeedbackDirector.Play`가 결과 대기까지 마쳐야 다음 행동으로 넘어가며, 그 다음에 기존 약 0.6초(1x)의 행동 간 대기를 거친다. 배속과 스킵은 이 대기에도 적용한다. 피해 계산·턴 순서·보상은 유지한다.

## 2026-11-18 후속: 퇴각 포지션 선택 비활성화와 조건 완화

퇴각한 포지션의 선택창을 닫고 Position 버튼의 클릭/Collider2D를 비활성화한다. 버튼은 text_dim으로 표시한다. 포지션별 선택 매니저는 유지하되 `SelectionEnabled=false`로 직접 카드 입력도 거절한다. 이미 배정한 카드는 ResetSelection으로 소유를 해제하여 다른 포지션에 사용할 수 있게 한다. 현재 카드 입력 대상이 퇴각 슬롯이면 CardPositionManager는 입력 매니저를 반환하지 않는다.

전투 승인에는 기존 IsSlotCardReady/IsTargetReady의 퇴각 제외 규칙을 유지한다. 퇴각한 슬롯에는 카드·Front AT/DF·타깃이 필요하지 않고, 생존 슬롯에는 기존 조건이 모두 필요하다. 전원이 퇴각한 상태에서는 전투를 승인하지 않는다. `BattleAccessManager.Refresh`에서 실제 IsCombatActive 상태와 선택 매니저/포지션 버튼을 함께 동기화하며, 카드 해제에서 발생하는 재진입 Refresh는 가드한다. 관리 오브젝트 전체를 파괴/비활성화하여 정적 참조를 잃는 방식은 사용하지 않는다.

부활·예약 재배치는 기존 Operator의 Refresh 경로를 사용해 매니저와 버튼을 다시 활성화한다. 창은 해당 Position 버튼으로 다시 열 수 있으며 카드 배정은 새로 해야 한다. 캐릭터 스탯·퇴각/재배치의 턴 규칙·카드 수·공격 계산은 변경하지 않았다.
