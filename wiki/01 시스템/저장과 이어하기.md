# 저장과 이어하기

## 사용 흐름

- Map 좌측 상단의 설정 버튼: 화면 전체에 50% 검정 오버레이와 저장/저장 후 나가기/닫기를 표시한다. 평상시에는 저장 버튼들을 숨긴다.
- 설정의 저장: 슬롯 선택 창에서 저장할 위치를 선택한다. 기존 기록이 있으면 덮어쓰기를 두 번 확인한다. 슬롯 선택 취소 또는 저장 완료 후 설정 창으로 돌아온다.
- 저장 후 나가기: 슬롯 저장 성공 시에만 Lobby로 돌아간다.
- Lobby의 이어하기 폴더: 페이지당 10개 슬롯과 선택한 파일 요약, 계속하기/삭제를 제공한다.
- 처음에는 10개 슬롯(1페이지)이다. <, >로 페이지를 이동하고 +를 누를 때마다 10개짜리 페이지를 추가한다. 빈 페이지도 재실행 후 유지한다.
- 삭제는 두 번 눌러 확인한다. 창을 닫거나 슬롯·페이지를 바꾸면 확인이 취소된다. 손상되거나 종료된 파일도 삭제할 수 있다. 선택한 슬롯의 본 파일/백업/임시 파일만 삭제하며 슬롯 번호·다른 파일·페이지 수는 유지한다.
- 새 게임은 메모리의 판을 초기화하지만 기존 파일은 보존한다. 다음 명시적 저장에서 슬롯을 덮어쓴다.
- 파일 삭제는 저장 슬롯만 지운다. 현재 메모리의 판이나 게임 정의 JSON은 변경하지 않는다.

## 저장 범위

`RunSaveSnapshot` schemaVersion 2: 판 GUID·UTC 저장 시각·진행/종료 상태, 아군 대원 ID, 보유 Cache ID와 판 전체 구매 이력, Packet·Layer·현재 EXP, 무결성/정합성, 현재/방문/완료 노드 ID, 마지막 전투 노드와 승패를 기록한다. 이전 v1 파일은 두 HP를 100%로 준비 복원하며 원본 파일은 읽기만으로 변경하지 않는다. 아군은 각 Position에 한 명씩 세 명이다. 맵 표시 정보는 기존 Scene 데이터에서 복원한다.

전투 HP·퇴각·SP·카드 선택·일시적 연출은 저장하지 않는다. 다음 전투에서는 저장된 대원 구성과 Cache를 기준으로 전원을 새로 생성한다. 현재 구현되지 않은 루트/엔딩/웨이브 상태는 포함되었다고 간주하지 않는다. 향후 상태 추가 시 DTO·버전·검증·테스트도 확장해야 한다.

## 제한과 안전성

- 저장 경로: `Application.persistentDataPath/Saves/`. 1번 슬롯은 기존 `run.json`을 그대로 사용하고, 2번 이후는 `slot_0002.json`, `slot_0011.json` 등이다. 페이지 수는 작은 `pages.json`에 별도 기록한다. +는 빈 저장 파일 10개를 미리 생성하지 않는다. 개발용 `Resources/GameData` 정의와 별개다.
- Map의 안정된 상태에서만 저장한다. 전투·Shop·로딩 중에는 저장하지 않는다.
- 계속하기는 Lobby에서만 시작하며 파일을 다시 검증한 후 Map 활성화 전에 준비된 상태를 적용한다.
- 각 슬롯 파일에 1 MiB 제한, JSON 문법·버전·체크섬·대원/Cache/노드 참조·중복·재화/EXP 범위를 검사한다. 실패 시 현재 판을 변경하지 않는다.
- 완성된 `.tmp`를 디스크에 기록한 뒤 원본을 교체하며 이전 파일은 `.bak`로 남긴다. 종료 판을 되살리지 않도록 백업을 자동 계속하기 대상으로 쓰지 않는다.
- 삭제는 `.tmp`, `.bak`, 본 파일 순으로 제거한다. 체크섬은 손상 검사용이며 암호화나 치팅 방지 기능은 아니다.
- `RunSaveService.MarkRunEnded("Ending" 또는 "Ejected", out error)`는 같은 runId의 모든 슬롯을 종료 처리한다. 무결성 0% 사출 후 다른 슬롯의 사본으로도 계속하기할 수 없다. 다른 판은 보존한다. 확인된 동일 판의 종료 기록 실패 시 해당 슬롯만 삭제를 시도하며 IO 실패는 로그로 알린다. 읽지 못한 파일을 임의 삭제하지 않는다. 최종 보스/유물 엔딩 연결은 조건 확정 후 진행한다.

## 담당 코드와 검증

`Assets/Script/RunSave/`: DTO, 바인딩, 준비/검증 복원, 파일 저장소, 서비스, Map 버튼, Lobby 창. `Resources/RunSaveBindings.asset`은 저장 가능한 대원/Cache/노드와 Scene 참조를 연결한다. 표시 문구는 `Resources/GameData/Localization/ko-KR/save.json`이다.

파일 왕복·손상/비호환/잘못된 값 거절·실패 상태 보존·교체·종료·삭제·IO 오류를 검증했다. 제한 플레이 1회로 Map 저장 → Lobby 메모리 초기화 후 계속하기 → 전투 저장 금지/전원 초기 HP → Map → Lobby 확인 삭제를 검증했다. 테스트는 임시 폴더로 격리하여 실제 사용자 저장을 건드리지 않았다. 실제 마우스/해상도별 시각 QA는 별도다.

다중 슬롯 확장 검증: 기본 10개·+10개·빈 페이지 재로드·슬롯별 저장/백업/삭제·같은 판 사본 종료·다른 판 보존 통과. 제한 UI 이벤트 검증에서 Map 1/11번 저장, 덮어쓰기 확인, Lobby 페이지 추가/탐색/선택 취소, 11번 계속하기, 12번 추가 저장 및 11번만 삭제를 확인했다. 슬롯 크기/텍스트 높이도 검사했다.

설정 이동 검증: 기본 숨김·좌측 상단 앵커·오버레이 RGBA(0,0,0,0.5)·UI 레이캐스트 차단·닫기·슬롯 취소/저장 후 설정 복귀·저장 후 로비를 기존 다중 슬롯 제한 UI 경로에서 확인했다. 설정과 슬롯 선택 오버레이는 동시에 쌓지 않는다.
