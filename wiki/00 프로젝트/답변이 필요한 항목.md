# 답변이 필요한 항목

사용자 결정이 필요한 질문을 모으는 기준 문서다. 미입력 답변은 확정 규칙으로 취급하지 않는다. 질문 ID를 함께 적어 대화 또는 이 문서에서 답변할 수 있다.

## 관리 규칙

- 새 질문이 생기면 여기에 고유 ID, 질문, 필요한 이유, 관련 문서, 답변란과 상태를 기록한다.
- 상태는 `답변 대기`, `답변 완료`, `보류`로 구분한다. 체크박스는 답변 확정 여부이며 구현 완료 여부가 아니다.
- 답변을 받으면 사용자 답변과 날짜를 기록하고 관련 시스템 문서·TODO를 동기화한다. 기존 답변을 바꾸면 변경 이력을 남긴다.
- 이미 확정된 결정을 다시 질문하지 않는다. 애매한 부분만 별도 질문으로 분리한다.
- 답변에 의존하는 동작은 확정 전 구현하지 않는다. 관련 없는 기술 작업은 계속 진행할 수 있다.
- 과거 대화에서 확인된 결정과 AI 제안을 구분한다. 부분 답변은 기록하되 남은 질문이 있으면 답변 대기 상태를 유지한다.

## 먼저 답변 필요 · Cache와 상점

### Q-C01 · Cache 유지 기간

- [x] 답변 확정
- 질문: 구매한 Cache의 유지 범위와 새 게임 초기화 시점은 무엇인가?
- 필요한 이유: 보유 상태 저장, 씬 전환, 새 런 초기화 범위를 정해야 한다.
- 사용자 답변(2026-10-13): 로비와 전체 사이클이 있으며 여러 전투를 진행한다. 유물에 따라 엔딩이 바뀌고 루트별 전투가 있을 예정이다. 무결성과 정합성 시스템을 넣을 예정이다.
- 확인된 방향: 단일 전투의 패배만으로 게임 전체 흐름을 정의하지 않고 로비·사이클·루트·엔딩을 함께 설계한다.
- 추가 사용자 답변(2026-10-15, Q-C01++): 구매 후 한 판 동안 계속 보유하고 효과가 유지된다. 추후 교환·합성 노드로 사라지거나 다른 Cache가 될 수 있다. 로비에서 새로 시작하기로 새 판을 시작할 때 Cache 등 게임 정보를 basic 상태로 초기화한다. 다회차 게임이며 계정 영구 해금과 혼동하지 않는다.
- 상태: 답변 완료 — 전투/맵 전환으로 초기화하지 않고 명시적 새 게임에서 초기화

### Q-C02 · 직군·세부직군 모델

- [x] 답변 확정 — 직군 3개
- 질문: '직군'과 '세부직군'을 어떻게 구분하는가? 현재 코드는 `OperatorPosition`(Front/Middle/Back)과 `OperatorClass`(Defender/Guard/Vanguard/Caster/Sniper/AttackHealer/Healer/Supporter)를 가진다. 이 모델을 그대로 쓰는가, 별도 직군·세부직군을 추가하는가?
- 필요한 이유: Cache가 영향을 주는 대원을 정확히 필터링해야 한다. 포지션을 직군으로 임의 해석하지 않는다.
- 사용자 답변(2026-10-13): 직군은 FRONT, MIDDLE, BACK 총 3개이며 현재 포지션이 곧 직군이다. 세부 직군은 추후 알려준다.
- 구현 매핑: 직군은 기존 `OperatorPosition`을 사용한다. 현재 `OperatorClass` 목록을 최종 세부 직군으로 확정하지 않는다.
- 상태: 답변 완료 — 직군 매핑 확정, 세부 직군 목록은 보류

### Q-C03 · 임시 Cache 6종의 대상

- [x] 답변 확정
- 질문: 생명력·공격력·방어력·아츠 저항·공격 속도·종합 강화 Cache 각각을 어떤 직군/세부직군 또는 전체 아군에 적용하는가? 재화/경험치 획득 버프 Cache는 이 6종 중 일부를 바꾸는가, 나중에 별도로 추가하는가?
- 필요한 이유: 강화 대상 범주는 확정되었지만 상품별 대상과 구성은 아직 없다.
- 사용자 답변(2026-10-13): 현재는 글로벌 버프를 사용한다. 재화·경험치 버프 Cache 한 개를 추가하여 총 7개로 한다.
- 확정 구성: 기존 능력치 강화 6종은 전체 아군 대상. 7번째 Cache 한 개가 Packet·경험치 획득량을 강화한다. 구체 수치/연산/가격은 Q-C06에서 확인한다.
- 상태: 답변 완료 — 7종 모두 설정·구매/적용 가능

### Q-C04 · 최대 HP 강화

- [x] 답변 확정
- 질문: 최대 HP가 증가할 때 현재 HP는 그대로, 증가량만큼 회복, 기존 HP 비율 유지 중 어떤 방식인가? 퇴각 대원에게도 최대 HP 보너스가 적용되는가? HP 강화 자체가 부활을 일으키는가?
- 필요한 이유: 강화와 회복·퇴각·재배치 처리의 충돌을 방지해야 한다.
- 사용자 답변(2026-10-13): 퇴각을 개별 전투 사이에 이어 적용하지 않는다. 1번 전투에서 퇴각했어도 2번 전투에서는 전투할 수 있다.
- 확정 내용: 퇴각 상태는 다음 전투로 이월하지 않는다.
- 추가 사용자 답변(2026-10-15): 기준이 될 기본 HP와 Cache의 +N 또는 N% 계산 후 전투에서 사용하는 실제 HP를 분리한다. 원본 기본 HP를 직접 변경하지 않는다.
- 남은 질문: 최대 HP 강화 시 현재 HP를 그대로 두는가, 증가량 회복인가, 비율 유지인가? 다음 전투의 시작 HP는 어떻게 정하는가? 현재 전투 중 HP 강화가 퇴각 대원을 부활시키는가?
- 추가 사용자 답변(2026-10-15): 퇴각은 해당 전투 Scene에서만 의미가 있다. Map에서는 퇴각을 계산하지 않으며 다음 전투에서는 모든 대원이 살아 있다. 퇴각을 저장/이월하지 않는다.
- 상태: 답변 완료 — 전투 생성 시 기본/실제 HP 분리와 새 활성 상태 적용. 미래 전투 중 Cache 교환은 별도 확정 전 보류

### Q-C05 · 중복 금지와 상점 재고

- [x] 답변 확정
- 질문: 현재 확정된 중복 구매 금지는 '동일 상점에서 한 번'인가, '보유 중/런 전체에서 같은 Cache 한 번'인가? 임시 6종은 항상 전부 판매하는가? 상점을 닫거나 다시 방문하면 판매 완료 상태를 유지하는가?
- 필요한 이유: 구매 승인·판매 종료·재입장과 재고 저장 범위를 정해야 한다. 중복 구매 금지 자체는 다시 결정할 필요가 없다.
- 사용자 답변(2026-10-15): 중복 구매 금지는 한 판 전체에 적용한다. 마지막 보스 처치 또는 무결성과 정합성이 모두 떨어져 사출되는 완전 패배까지 같은 판이다. 상인은 한 명이며 상점별 중복 제한이 아니다.
- 구현 방향: 판 전체 구매 이력과 현재 보유 목록을 분리한다. 교환·합성은 아직 구현하지 않는다.
- 추가 사용자 답변(2026-10-15): 임시 7종을 판매한다. 가격은 AI가 8~32 Packet 범위에서 책정한다. 별도 Shop Scene에서 구매한다.
- 상태: 답변 완료 — 7종 고정 카탈로그, 한 판 구매 이력 유지. 임시 가격 HP 12/공격 16/방어 12/저항 8/속도 20/종합 32/보상 24

### Q-C06 · Packet·경험치 획득 버프

- [x] 답변 확정
- 질문: 7번째 재화·경험치 Cache의 가격과 두 강화량은 얼마인가? 고정량 추가인가, 비율 증가인가? Packet 버프는 전투 승리 8개뿐 아니라 Layer 상승 10개에도 적용되는가? 여러 버프의 합산/곱연산과 정수 반올림은 어떻게 처리하는가?
- 필요한 이유: 기본 보상은 확정되어 있으나 Cache에 의한 보상 증폭 규칙은 없다.
- 사용자 답변(2026-10-15): +50%로 한다. Layer 요구 EXP나 Layer 상승 추가 Packet에는 관여하지 않고 획득 경험치에 적용한다. 무조건 반올림한다.
- 해석/구현: 승리 Packet 8→12, EXP 12→18, Layer 상승 추가 Packet 10 유지, 요구치 유지. 0.5는 올림한다.
- 상태: 답변 완료

### Q-C07 · HP 비율 계산과 전투 중 변경

- [x] 답변 확정
- 질문: 기본 HP에 고정 보너스와 비율 보너스가 함께 있으면 어느 순서로 계산하고 정수 소수점은 어떻게 처리하는가? 전투 중 Cache를 획득/교환/합성할 수 있는가? 가능하다면 현재 HP는 유지/증가량 회복/비율 유지 중 무엇이며 퇴각 대원을 부활시키는가?
- 사용자 답변(2026-10-15): 기본 고유 스탯을 기준으로 계산하고 전투 스탯에 더하는 합연산을 사용한다. 추후 모든 합연산이 끝난 스탯에 추가 +N%를 적용하는 상위 Cache를 추가한다.
- 상태: 답변 완료 — 현재 등급은 원본 기준 합산. 상위 곱연산 Cache는 미래 작업이며 전투 중 교환/합성은 미구현

## 재질문하지 않을 확정 사항

- 새 런 Packet 30개, 전투 승리 Packet 8개·경험치 12, Layer 상승당 Packet 10개.
- Layer 요구 경험치는 최초 16에서 1.5배 복리 증가. 현재 구현은 소수 올림·잔여 경험치 이월이다.
- Cache 강화 대상 범주는 직군·세부직군·전체 아군·재화/경험치 획득량.
- 현재 직군은 FRONT/MIDDLE/BACK = `OperatorPosition`. 최종 세부 직군 목록은 추후 결정한다.
- 임시 Cache는 글로벌 적용이며 기존 6종에 Packet·경험치 버프 1종을 더해 7종으로 구성한다.
- 전투 1에서 퇴각했어도 전투 2에서는 전투할 수 있다. 퇴각 상태를 전투 사이에 이월하지 않는다.
- 현재 Cache 중복 구매 금지. 미래에 일부 상품의 N개 중복·부품 조합을 추가할 수 있지만 지금은 구현하지 않는다.
- Cache는 한 판 전체에 유지되며 로비에서 새 게임을 시작할 때 기본 상태로 초기화한다. 중복 구매 금지도 한 판 전체에 적용한다.
- HP는 원본 기본값과 Cache 계산 후 전투값을 분리한다.
- 로딩 이미지는 미확정으로 유지하며 안내·분위기 표현에 TMP 사용 가능.
- 플레이 테스트는 필요한 범위로 제한한다.
