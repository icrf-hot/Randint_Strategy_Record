# 프로젝트 개요

## 한 줄 정의

카드의 숫자와 속성을 세 포지션의 대원 행동으로 변환하고, 노드형 맵을 이동하며 진행하는 명일방주 팬게임 프로토타입.

## 현재 플레이 구조

1. `Map_1F` 씬에서 현재 노드와 연결된 다음 노드를 확인한다.
2. 노드를 클릭해 카메라를 집중시키고 설명과 선택지를 연다.
3. Battle 노드 선택 시 맵의 로딩 오버레이를 페이드인하고 `Playing_Scene`을 비동기로 불러온다.
4. 전투 씬의 진입 오버레이가 문구를 표시한 뒤 페이드아웃한다. 이 동안 게임 시간은 정지하며 입력을 차단한다.
5. 진입 페이드가 끝나면 총 6장의 카드를 받는다. 각 자리는 숫자 카드가 기본이며, 확률 판정을 통과하면 묶음 전체에서 최대 1장이 특수 카드 `T`로 대체된다.
6. 활동 중인 Front, Middle, Back 슬롯에 각 규칙에 맞게 카드를 배분한다. 퇴각한 슬롯은 카드·행동·타깃 선택을 요구하지 않는다.
7. 필요한 공격 대상까지 지정하면 전투 버튼이 열린다.
8. 공격 속도순으로 아군과 적이 한 번씩 행동한다.
9. 각 행동 직후 생존 적이 있는지 확인한다.
10. 행동 반복 종료 후 예약 재배치를 처리한다. 활동 가능한 대원이 없으면 실패 결과 화면으로 진행한다.
11. 전투가 계속되면 선택 카드를 초기화하고 새 카드를 배분한다. 일반 라운드 임시 보너스 초기화는 현재 누락되어 수정이 필요하다.
12. 모든 적 처치 또는 패배 시 `FinishBattle()`이 보너스를 초기화하고 성공/실패 결과 화면을 표시한 뒤 `Map_1F`을 비동기로 불러온다.
13. `MapRunState`에 저장된 노드 ID를 현재 위치로 복원하고 맵 진입 페이드를 끝낸다.

현재 맵→전투→승리→맵 복귀와 현재 노드 복원은 코드·씬 참조상 🟢 연결되어 있다. 다만 이번 확인은 Read Only 정적 검증이며 실제 플레이는 🟡 미검증이다. 로딩 오버레이는 Sprite 없는 검은색 UI Image를 사용하는 임시 연출이고, 패배와 성공/실패 결과 표시는 🟢 정적 구현 확인 상태이며 디스크 기반 저장·불러오기는 🔴 미구현이다. 현재 노드 ID·표시명·복귀 플래그는 프로세스 메모리의 정적 상태로만 유지된다. 문구·대원/적/스킬 기본 정의는 [[02 데이터/JSON 데이터 관리|JSON 데이터 관리]]를 기준으로 조회한다.

## 핵심 설계 축

| 축 | 역할 | 현재 상태 |
|---|---|---|
| 카드 | 매 라운드 행동 자원 | 🟢 구현 |
| 포지션 | Front 공격/방어, Middle 공격, Back 회복 | 🟢 구현 |
| 타기팅 | 포지션별 적 선택 제한 | 🟢 구현 |
| 턴 순서 | 공격 속도 내림차순, 동률 우선순위 | 🟢 구현 |
| 맵 | 연결 노드 탐색과 이동 가능 노드 표시 | 🟢 구현 |
| 씬 전환 | 맵 퇴장 페이드 → 비동기 로드 → 전투 진입 페이드 | 🟢 구현 |
| 로딩 화면 | 페이드·문구·점 애니메이션 | 🟢 구현 |
| 로딩 이미지 | 양쪽 오버레이의 최종 배경·연출 자산 | 🟡 부분 구현 |
| 이벤트 선택 | 선택지 표시와 노드 이동 | 🟡 부분 구현 |
| 스킬 | SP 데이터와 충전 모델 | 🟡 부분 구현 |
| 승리 후 복귀 | 모든 적 처치 → `Map_1F` → 현재 노드 복원 | 🟢 구현 |
| 런 컨텍스트 | 현재 노드 ID의 메모리 내 유지 | 🟡 부분 구현 |
| 패배·결과 화면 | 재배치 후 활동 대원 검사 → 결과 표시 → 맵 복귀 | 🟢 구현 |
| 일반 라운드 정리 | 임시 보너스 초기화 | 🟡 수정 필요 |
| 데이터 관리 | JSON 기본 정의·문구 조회와 키/ID 연결 | 🟢 구현 |
| 저장 | 런 상태 디스크 영속화 | 🔴 미구현 |

## 후속 UI 기획 · 아직 미구현

[[04 기획/타이틀·로비 기획|타이틀·로비 기획]]에 Title→XP 느낌의 로비와 설정·폴더 이어하기·문서형 새 게임 `.exe`, Map 창 조작 `− / □ / ×`, Battle 일시정지 `나가기 / 계속하기` 요구가 기록되었다. 초기 UI는 이미지 없이 TMP와 Square로 구성하는 방향이다. 이는 현재 플레이 구조에 연결된 기능이 아니며 저장·복귀·중단 정책을 확정한 뒤 구현해야 한다.

팬게임의 자체 설정으로 PRTS의 배신 때문에 작전기록의 문제를 의심하고 내부 데이터에 직접 접근한다는 컨셉이 기록되었다. 원작의 공식 설정과 구분한다.

## 주요 씬

- `Title.unity`: Main Camera만 존재하는 초기 상태
- `Map_1F.unity`: 8개 노드로 구성된 3D 경로, 포커스 UI, 전투 씬 로더
- `Playing_Scene.unity`: 카드 선택, 대원 포커스, 적 생성·타기팅, 턴 실행
